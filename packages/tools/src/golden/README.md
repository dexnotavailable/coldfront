# Deterministic chunk goldens

Phase 1.2 coverage: **300 chunks**, comprising 150 preserved test-world records and 150 main-world records across seeds 1, 2 and 3. Each main seed has both LOD0 and LOD1 samples in all sixteen surface regions, ten transition samples, four frame samples and four vertical samples. The original test addresses and all four hashes per record remain unchanged. No LOD2–6 column tiles are claimed.

The portable `core.ts` runs `generateWorldChunk` with the actual main/test WorldContext. Its per-run resolver caches one plan/context per world and seed for address selection and generation. It hashes **all** core block IDs, halo block IDs, Float64 density and Float64 column data separately with standard SHA-256, validating each context's exact column stride. Encoding is explicit little-endian uint16 and IEEE binary64, preserving signed zero and infinities; NaNs fail. This is independent of native typed-array byte order and does not round floats to conceal disagreements. Node and browsers execute the same harness and actual generator.

Baseline: `packages/shared/test/golden/worldgen.json`, matching terrain section 14.7. The ordinary Node-only Vitest suite collects `packages/shared/test/golden.test.ts`. It verifies schema, sample set, generator version and each field hash. Sample definitions and fixed XZ anchors are versioned in `core.ts`; surface cy is derived from the centre-column height and frozen into the fixture. A changed sample set cannot silently reduce coverage. Provenance records the actual source hash, Git commit and Node version used to generate the baseline; cosmetic source-only edits do not require a baseline rewrite when generated bytes remain identical.

## Commands

Run from the repository root:

```text
npm run golden:update
npm run test:golden:browsers
```

Equivalent direct commands are:

```text
node --import tsx packages/tools/src/golden/update.ts
node node_modules/vitest/vitest.mjs run packages/shared/test/golden.test.ts
node --import tsx packages/tools/src/golden/browsers.ts
```

`golden:update` always regenerates the complete set; there is no subset-update flag. It compares the newly generated test-world records to the previous 150 and refuses to write if any address or hash changed. Review main-world changes and bump `WORLDGEN_VERSION` at most once per PR when generated output changes. A baseline update is not a substitute for investigating an unintended regression. Root owns version and source changes.

## Browser policy

The runner starts a dedicated loopback-only Vite server with the portable test entry. It does not load the game UI, visit a public site or request external assets. Browser processes run sequentially and are closed before the server closes. Receipts go to `out/step4/golden-browsers.json`.

- Default matrix: Chromium, Firefox, WebKit.
- In CI (`CI` truthy) or with `--require-all`, **all three must execute and pass**. A subset request or a missing executable fails the run. The shipped CI already installs all three before running this script; no workflow edit is needed.
- Locally, missing executables produce explicit `skip` records with their resolved paths. At least one browser must actually pass. Partial availability is labelled `partial-local-pass`, never full three-browser proof.
- An installed browser that fails to launch, a page error, a changed sample contract or any mismatched hash fails; these are not converted into availability skips.
- There are no browser downloads in this runner. It honours `PLAYWRIGHT_BROWSERS_PATH` before importing Playwright; otherwise it selects the established `D:/Dex/Temp/ms-playwright` cache when present, then falls back to Playwright's platform default. The receipt records that discovery choice. It uses the pinned package, existing `CF_CHROMIUM`/proven Windows Chromium route, and optional `CF_FIREFOX`/`CF_WEBKIT` executable paths. A local subset can be chosen with `--browsers chromium,firefox`; CI cannot use that to weaken its matrix.

Reserve the sampling/browser lane before full golden or browser runs, and do not overlap benchmarks, atlas/slice generation or rendering. The implementation uses only existing dependencies: Playwright, Vite and tsx plus Node/Web Crypto.
